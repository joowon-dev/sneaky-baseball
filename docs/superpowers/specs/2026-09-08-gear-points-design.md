# 포인트와 배트 — 설계

2026-09-08

## 무엇을 만드는가

안타·홈런을 치면 **포인트**가 쌓이고, 그 포인트로 **배트**를 사서 바꿔 낀다.
센 배트는 공을 더 멀리 보낸다. 같은 값이 **구단 응원 포인트**로도 쌓여, 나중에
온라인 랭킹(다음 사이클)이 그대로 집어 갈 원장이 된다.

이 문서는 셋 중 첫 덩어리(**B. 포인트·아이템**)만 다룬다. 나머지 둘은 각자 사이클을 갖는다.

- **A. 배포** — dmg/exe + 자동 업데이트
- **C. 온라인 응원 랭킹** — 서버·계정·집계

## 확정된 결정

### 강화는 밀고, 기록은 가른다

배트가 세지면 홈런이 쉬워진다. 그러면 **최고 비거리 기록의 잣대가 매번 달라진다** —
`CLAUDE.md` 가 「최고 비거리 기록을 하나로 두기 때문에 투수 거리 범위를 좁게 둔다」고
못 박아 둔 바로 그 전제다. 그래서 기록을 둘로 가른다.

| | 갱신 조건 |
|---|---|
| `bestMeters` — **맨몸 기록** | 힘 배수가 정확히 1일 때만 갱신 |
| `bestGearedMeters` — **장비 기록** | 언제나 갱신 |

기존에 저장된 `bestMeters` 는 전부 맨몸으로 세운 것이므로 뜻이 그대로 남는다.

### 통장을 둘로

| | 쌓이는 것 | 줄어드는 것 |
|---|---|---|
| **지갑** `points` | 안타·홈런 | 배트를 사면 준다 |
| **응원** `cheer[teamId]` | 같은 값 | **절대 안 준다** — 랭킹 원장 |

응원 원장을 소비에서 떼어 놔야, C 가 「이 사람이 이 구단에 넣은 총량」을 그대로 보낼 수
있다. 지갑만 남기면 배트를 살 때마다 응원이 깎여 랭킹이 흔들린다.

- 홈런 = 비거리 m 그대로, 안타 = `round(m × 0.4)`
- **아웃·파울·헛스윙은 0점.** 아웃은 여전히 잃는 게 없다 — 얻는 것도 없을 뿐이다
- 응원은 **타자 유니폼의 구단**에 적립한다. 「유니폼 없음」이면 적립처가 없어 지갑만 쌓인다

### 배트는 색과 굵기로 말한다

`src/game/gear.js` 가 `teams.js` 처럼 순수 데이터를 갖는다. 배수와 생김새가 한 줄에 있다.

| 키 | 이름 | 값 | 힘 배수 |
|---|---|---|---|
| `bare` | 맨손 배트 | 0 | 1.00 |
| `ash` | 물푸레 | 800 | 1.04 |
| `maple` | 메이플 | 2,500 | 1.08 |
| `birch` | 자작 | 6,000 | 1.12 |
| `carbon` | 카본 | 15,000 | 1.16 |

가격과 배수는 **손맛으로 정하는 값**이다. 배수 1.16 이면 발사 속도가 16% 늘고 비거리는
대략 그 제곱을 따라 35%쯤 늘어난다.

색과 **배럴 굵기**(`tip`)가 배트마다 다르다 — 숫자만 다르면 산 보람이 눈에 안 보인다.
길이는 건드리지 않는다. 뼈대(`batBone`) 좌표라 포즈를 다시 그려야 해서 대가가 크다.

### 물리는 인자로 주입한다

`battedFlight(result, errorMs, lane, launchDy, powerMul = 1)` — 인자를 **맨 뒤에 하나** 더
받아 발사 속도에 곱한다. `MAX_SPEED` 상수는 건드리지 않는다. 상수를 고치면 결정론이
깨지고, 테스트가 옛 값과 새 값을 구분하지 못한다.

홈런·아웃 판정은 손댈 게 없다 — `engine` 이 궤적을 보고 정하므로, 배트가 세지면 담장을
넘는 공이 저절로 늘고 뜬공이 멀어져 외야수가 못 따라잡는다.

`powerMul = 1` 이면 궤적이 **예전과 완전히 같아야 한다**. 테스트가 이걸 못 박는다.

### 상점은 두 번째 웹뷰 창

오버레이는 클릭이 전부 통과한다. 사람이 만질 수 있는 표면은 지금 투수 히트박스 하나뿐이라
상점을 얹을 자리가 없다. **셸이 보통 창을 하나 더 띄우고** `src/shop/index.html` 을 얹는다.

- UI 를 **한 번만** 만들면 맥·윈도우가 같이 쓴다 (네이티브로 짜면 두 벌이 된다)
- 배트 미리보기를 `sprites.js` 로 그대로 그린다 — 내가 고른 유니폼을 입은 타자가 그 배트를 든다
- 오버레이는 그대로 통과 유지. 「몰래」가 안 깨진다

### 저장은 셸이 한다

유니폼·투수 거리·기록과 같은 자리(맥 `UserDefaults`, 윈도우 `state.json`). 창이 둘이라
**하나의 진실**이 필요하고, C 가 보낼 데이터도 셸이 이미 들고 있는 게 된다.

저장하는 것: `points` · `owned[]` · `equipped` · `cheer{}`.

### 브리지 — 셸은 산수만 한다

| 메시지 | 보내는 쪽 | 셸이 하는 일 |
|---|---|---|
| `earn {points, team}` | 게임 창 | `points += p`, `cheer[team] += p` |
| `buy {key, price}` | 상점 창 | 못 샀으면 무시. 샀으면 `points -= price`, `owned += key` |
| `equip {key}` | 상점 창 | 안 가진 것이면 무시 |

**가격표를 셸에 두지 않는다.** 두면 Swift·C#·JS 세 벌이 되어 언젠가 어긋난다. 값은
상점(JS)이 순수 모듈에서 읽어 보내고, 셸은 더하고 빼기만 한다. 셸이 검증하는 건
「가진 돈으로 되는가 / 이미 가졌는가」 두 가지뿐이다.

바뀐 뒤에는 셸이 **두 창 모두에** `window.__sneakyGear(state)` 를 밀어 넣는다 —
게임 창에서 번 포인트가 열려 있는 상점에 바로 보이고, 상점에서 바꿔 낀 배트가
바로 타석에 선다.

주입하는 JS 는 **손으로 조립하지 않고 직렬화한다**(`JSONSerialization` / `JsonSerializer`).
따옴표 하나가 새면 `window.sneaky` 가 통째로 안 만들어지고 핫키까지 조용히 죽는다.

## 구조

새로 생기는 것:

- `src/game/gear.js` — 배트 데이터(순수). 가격·힘 배수·색·굵기
- `src/game/wallet.js` — 지갑·응원·소유(순수). 벌기·사기·바꿔 끼기
- `src/shop/` — 상점 창의 HTML·CSS·JS
- `test/gear.test.js` · `test/wallet.test.js`

손대는 것:

- `src/game/batted.js` — `battedFlight` 에 `powerMul` 인자
- `src/game/engine.js` — `powerMul` 을 들고 궤적에 넘긴다. 기록을 둘로 가른다
- `src/render/sprites.js` — 배트 색·굵기를 인자로 받는다
- `src/render/draw.js` — 배트를 실어 나른다
- `src/renderer/app.js` — 결과가 날 때마다 벌고, 셸에 알린다
- `mac/Sources/main.swift` · `windows/Program.cs` — 저장·상점 창·트레이 「상점」
- `mac/build.sh` · `windows/SneakyBaseball.csproj` — `src/shop` 도 실어 나른다

## 테스트

순수 모듈만 본다(지금 규칙 그대로). **통과만 하는 테스트는 안 된다** — 값을 못 박는다.

- `gear.test.js` — 배트 키·가격·배수를 값으로 못 박는다. 맨손이 1.00 인 것, 목록이 값 순인 것
- `wallet.test.js` — 홈런 100m 가 100P, 안타 100m 가 40P, 아웃·파울·헛스윙 0P.
  **배트를 사도 `cheer` 가 안 줄어드는 것**. 돈이 모자라면 안 사지는 것. 유니폼 없으면 응원 적립 없음
- `batted.test.js` — `powerMul` 1 이 기존 궤적과 같은 것(회귀), 1.16 이 비거리를 정해진 만큼 늘리는 것
- `engine.test.js` — 맨몸 기록이 **배수 1 일 때만** 갱신되고, 장비 기록은 언제나 갱신되는 것

상점 창·배트 그림은 눈으로 본다.
