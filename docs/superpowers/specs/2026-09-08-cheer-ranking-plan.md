## B 가 이미 깔아 둔 것

랭킹이 집계할 데이터는 **이미 로컬에 쌓이고 있다.**

```json
"cheer": { "lotte": 5400, "kia": 1200 }
```

구단별 누적이고, **배트를 사도 줄지 않는다.** 그래서 「이 사람이 이 구단에 넣은 총량」이
언제나 참이다. C 가 할 일은 이걸 서버로 보내고, 전 유저 합계를 받아 보여 주는 것뿐이다.

## 어떻게 보내는가

**델타를 보낸다.** 마지막으로 보낸 값과 지금 값의 차이만 올린다 — 총량을 그대로 올리면
같은 값이 여러 번 더해지거나(재시도), 기기를 두 대 쓰는 사람의 값이 서로를 덮어쓴다.
셸이 `cheerSent` 를 따로 저장하고, `cheer - cheerSent` 만 올린 뒤 성공하면 옮겨 적는다.

보내는 때: **5분마다, 그리고 앱을 끌 때.** 홈런마다 보내면 네트워크가 눈에 띈다 —
「몰래」 하는 앱이 몰래 하지 못하게 된다.

## 누가 보내는가 — 계정을 만들지 않는다

**설치할 때 기기마다 UUID 를 하나 발급**해 저장하고, 그걸 신분으로 쓴다.
로그인도, 이메일도, 비밀번호도 없다. 구단 랭킹은 **합계**라 누가 넣었는지 알 필요가 없다.

이러면 잃는 것도 있다 — 기기를 바꾸면 내 기여가 따라오지 않는다. 그건 개인 랭킹을
만들 때 다시 이야기하면 된다(아래 「정해야 할 것」).

## 어뷰징 — 막을 수 있는 만큼만 막는다

클라이언트가 보내는 숫자는 **믿을 수 없다.** 앱을 뜯어 「홈런 10억」을 보내는 걸 원천 봉쇄할
방법은 없다. 그러니 **못 막는다는 걸 인정하고**, 값싼 방어만 건다.

- 한 번에 올릴 수 있는 값의 **상한** — 5분 사이에 사람이 낼 수 있는 최대치는 계산할 수 있다.
  카본 퍼펙트 홈런이 212P 이고 홈런 하나에 최소 3초쯤 걸리니, 5분이면 넉넉잡아 21,000P 다
- 기기 토큰별 **시간당 요청 수 제한**
- 이상치는 **버리지 말고 표시해 둔다** — 나중에 사람이 보고 정할 수 있게

그리고 화면에 **「재미로 보는 집계」라고 적어 둔다.** 상금이 걸린 순위가 아니다.

## 무엇을 보여 주는가

상점 창에 탭을 하나 더 단다 — 「구단 응원 랭킹」.
10개 구단이 총 응원 포인트 순으로 서고, 내가 넣은 몫이 그 옆에 붙는다.
「내가 롯데 전체의 0.004%」 같은 한 줄이 있으면 다시 치게 된다.

## 정해야 할 것

1. **서버를 무엇으로 하는가.** Supabase(Postgres + Edge Function) 가 가장 빠르다 —
   이미 붙어 있고, 테이블 하나와 함수 하나면 끝난다. Cloudflare Workers + D1 도 된다.
   둘 다 이 규모에서는 공짜 구간 안이다
2. **개인 랭킹도 둘 것인가.** 두면 계정이 필요해지고(기기를 바꿔도 따라와야 하니까),
   그 순간 개인정보와 로그인이 생긴다. 구단 랭킹만이면 익명으로 끝난다
3. **시즌을 둘 것인가.** 누적만 두면 먼저 시작한 구단이 영원히 1등이다.
   주간·월간으로 끊으면 매주 판이 열린다
4. **오프라인일 때.** 지금 설계는 못 보내면 그냥 쌓아 두고 다음에 보낸다 — 이대로 좋은가

## 프라이버시

**개인을 식별할 수 있는 것은 하나도 안 보낸다.** 기기 토큰(무작위 UUID)과 구단별 증가분뿐.
이건 나중에 사이트에 한 줄로 적어 두는 게 좋다 — 바탕화면에 얹히는 앱이 네트워크를 쓰면
사람들은 당연히 궁금해한다.
