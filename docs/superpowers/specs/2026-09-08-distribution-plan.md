## 맥 — dmg

`hdiutil` 로 충분하다. 창을 열면 `.app` 과 `Applications` 바로가기가 나란히 놓이는
그 흔한 모양이고, 스크립트 스무 줄이면 된다(`create-dmg` 같은 의존성을 새로 들일 이유가 없다).

**공증은 zip 이 아니라 dmg 에 건다.** 지금 `notarize.sh` 는 zip 을 올려 스테이플하는데,
dmg 로 바꾸면 스테이플이 dmg 자체에 붙어서 받는 사람이 마운트만 해도 검증이 끝난다.

## 윈도우 — 설치본

- **Inno Setup** 이 가장 가볍다. 스크립트 한 장이고 CI(윈도우 러너)에서 그대로 돌아간다.
- **코드 서명이 없으면 SmartScreen 경고를 한 번 넘겨야 한다.** 이건 기술이 아니라 돈 문제다 —
  OV 인증서가 연 10만 원대, EV 는 그보다 훨씬 비싸고 평판이 즉시 붙는다.
  **살지 말지는 주인이 정할 일이다.** 안 사면 경고가 남고, 기능은 다 된다.

## 자동 업데이트 — 두 단계로 나눈다

한 번에 「내려받아 스스로 교체」까지 가면 위험 대비 이득이 나쁘다. 앱을 스스로 덮어쓰는
코드는 잘못되면 사용자 컴퓨터에서 깨지고, 이 앱은 **0.5MB** 라는 성질을 무기로 삼고 있어
Sparkle(맥) 같은 프레임워크를 담으면 그 성질부터 잃는다.

**1단계 — 알려만 준다.** 하루 한 번, GitHub Releases 의 최신 태그를 조회해
지금 버전보다 높으면 트레이 메뉴에 「새 버전 1.2.0 받기」를 띄운다. 누르면 브라우저로
릴리스 페이지를 연다. 셸 코드 서른 줄이고, 실패해도 게임에 아무 일도 없다.

**2단계 — 내려받아 갈아 끼운다.** 1단계가 자리를 잡은 뒤에.
맥은 dmg 를 받아 `~/Downloads` 에 두고 열어 주는 데까지만 해도 체감이 크게 다르다.

**어느 단계까지 갈지는 주인이 정한다.** 나는 1단계를 권한다 — 몰래 하는 게임에
자동 재시작만큼 눈에 띄는 것도 없다.

## 정해야 할 것

1. 윈도우 코드 서명 인증서를 살 것인가 (안 사면 SmartScreen 경고 유지)
2. 자동 업데이트를 1단계까지만 할 것인가, 2단계까지 갈 것인가
3. 업데이트 확인 주소를 GitHub Releases API 로 할 것인가, 사이트에 `latest.json` 을 둘 것인가
   (GitHub 은 공짜지만 앱이 github.com 에 붙는 게 보이고, 사이트는 내가 통제한다)
