## 확정된 결정

### 맥은 dmg, 윈도우는 설치본

- `./mac/dmg.sh` — `.app` 옆에 `Applications` 를 세운 그 흔한 창. `hdiutil` 스무 줄이면 된다
- `./mac/notarize.sh` — 서명 → 공증 → 스테이플. **zip 과 dmg 를 따로 공증한다.**
  앱을 공증한 것과 dmg 를 공증한 것은 다른 일이라, 스테이플이 dmg 에 박혀 있어야
  처음 여는 맥이 오프라인이어도 마운트가 통과한다
- `windows/installer.iss` — Inno Setup. **관리자 권한 없이**(`PrivilegesRequired=lowest`)
  사용자 폴더에 깐다. 조용한 업데이트에 UAC 창이 뜨면 안 된다

**둘 다 만든다: zip 과 dmg / zip 과 설치본.**
자동 업데이트가 받아 가는 것은 맥은 **zip**, 윈도우는 **설치본**이다 —
dmg 를 마운트해서 자기를 갈아 끼우게 하면 실패할 자리가 너무 많고,
윈도우 zip 은 어디에 풀지가 정해져 있지 않다.

### 업데이트는 두 단계이고, **눌러야만** 갈아 낀다

몰래 하는 게임에 자동 재시작만큼 눈에 띄는 것도 없다. 그래서 스스로 재시작하지 않는다.

**1단계 — 알린다.** 켠 지 20초 뒤 한 번, 그 뒤로 하루 한 번 GitHub Releases API 에
물어본다. 지금보다 높은 태그가 있으면 트레이에 「새 버전 v1.2.0 설치」가 생긴다.
없으면 메뉴에 **아무 흔적도 없다.** 실패는 조용히 삼킨다 — 새 버전을 못 찾는 것과
게임이 안 되는 것은 다른 일이다.

버전은 **숫자로** 비교한다(`isNewerVersion`). 문자열로 비교하면 1.10 이 1.9 보다 작다.

**2단계 — 누르면 받아서 갈아 낀다.**

| | 맥 | 윈도우 |
|---|---|---|
| 받는 것 | `SneakyBaseball-mac.zip` | `SneakyBaseball-win-Setup.exe` |
| 푸는 법 | `ditto -x -k` | 설치본을 `/SILENT` 로 돌린다 |
| **검증** | `spctl --assess` + 번들 id 대조 | 설치본 자체가 검증한다 |
| 갈아 끼우기 | `replaceItemAt` 로 번들 교체 | `CloseApplications` / `RestartApplications` |
| 다시 띄우기 | `openApplication` 뒤 종료 | 설치본이 다시 띄운다 |

**맥의 서명 검사가 이 기능의 핵심이다.** `spctl` 이 거절하면 **아무것도 건드리지 않고**
릴리스 페이지만 연다 — 남의 zip 을 받아 자기 자리에 넣는 일은 절대 없어야 한다.
권한이 없어 교체에 실패할 때도 같다.

### 확인한 것

실제로 돌려 봤다. 버전을 1.0.0 으로 낮춘 빌드를 띄우니 20초 뒤 트레이에
「새 버전 v1.1.0 설치」가 떴고, 눌렀더니 받아서 검증하고 번들을 갈아 끼운 뒤 다시 떴다
(`dist` 의 앱이 1.1.0 으로 바뀌었다).

## 남은 것 — 주인이 정할 일

- **윈도우 코드 서명 인증서.** 없으면 SmartScreen 경고를 한 번 넘겨야 한다.
  기능은 다 되고, 이건 돈 문제다
- **CI 의 맥 산출물은 임시 서명이라 배포에 쓰면 안 된다.** 자동 업데이트가 서명을 검사하므로
  임시 서명 zip 은 **설치되지 않고** 페이지만 열린다. 릴리스에 올릴 맥 파일은
  `./mac/notarize.sh` 로 만든 것으로 **갈아 끼워야 한다**
- 윈도우 설치본은 아직 한 번도 만들어진 적이 없다(이 맥에 `dotnet` 도 Inno Setup 도 없다).
  다음 태그에서 CI 가 처음 만든다
