# Sneaky Baseball — 데스크톱 오버레이 전환 설계

날짜: 2026-08-12
상태: 승인됨

## 바뀌는 것

전용 창(900×320 커스텀 패널)을 없애고, **화면 전체를 덮는 클릭 통과 투명 오버레이** 하나로
바꾼다. 선수들은 화면 왼쪽 아래에만 서 있고, 친 공은 그 영역을 벗어나 작업 중인 창 위로
포물선을 그리며 날아간다. 밑에서는 계속 일할 수 있다.

## 확정된 결정

- **입력**: `⌥Space`(Option+Space) 전역 단축키로 시작·스윙. 클릭 통과 오버레이는 포커스를
  받지 못해 일반 키 입력이 도달하지 않기 때문. `⌘⇧B`는 기존대로 숨김/복귀이며, 숨어 있는
  동안에는 `⌥Space` 등록을 풀어 다른 앱에 돌려준다.
- **배치**: 작은 플레이 박스(240×78)를 작업 영역 왼쪽 아래 구석에 고정. 타자·포수·투수·지면·담장·
  투구 궤적은 전부 박스 안. **타구만** 박스를 벗어나 화면 좌표로 날아간다.
  화면 폭 전체를 경기장으로 쓰는 안은 폐기 — 투구 거리가 늘어나 기존 타이밍 감각이 깨진다.
- **가독성**: 배경이 투명해 다크·라이트 앱 위 모두에 올라가므로, 실루엣과 공에 반투명 흰
  글로우를 깔고 그 위에 검은 몸통을 그린다.
- **크롬 없음**: 둥근 종이 패널, 상단 바, 드래그 손잡이, 닫기 버튼을 전부 제거한다.
  종료와 기록은 **메뉴바 트레이**(`⚾`)로 옮긴다. Dock 아이콘은 숨긴다.
- **상시 실행 대비**: 연속 3번 스윙하지 않으면 자동 투구를 멈추고 idle로 돌아가
  `⌥Space`를 기다린다. 하루 종일 켜둬도 방해되지 않게.
- **타구**: 땅에 닿으면 튀어오르고(`BOUNCE`), 튈 힘이 없으면 마찰로 감속하며 굴러
  스스로 멈춘 뒤 옅어져 사라진다. 타격점이 땅에서 떠 있는 높이를 `launchDy`로 넘겨
  실제 지면에서 튀게 한다.
- **타구 수명은 투구 간격과 무관**: `startPitch`가 `lastResult`를 지우지 않아, 다음 공이
  오는 동안에도 직전 타구가 계속 굴러간다. 덕분에 공을 느리게 굴려도 타석 박자가
  늘어지지 않는다. 궤적이 다음 공에 흔들리지 않도록 `lane`을 `lastResult`에 함께 남긴다.
- **잔상**: 점을 띄엄띄엄 찍으면 공이 여러 개로 보인다 — 지나온 자리를 한 줄로 잇는다.
- **영속화**: 창 위치·크기 저장은 삭제(디스플레이 크기에 종속). `bestStreak`만 남긴다.

## 좌표계

두 개를 쓴다.

1. **플레이 박스 좌표** — 기존 `geometry()` 그대로. 비율 상수(`BATTER_X`, `FENCE_X` …)와
   투구 궤적이 여기 산다. 박스 크기가 그대로라 지금 튜닝된 감각이 유지된다.
2. **화면 좌표** — `battedBall()`의 `dx`/`dy`를 그릴 때만. 단위를 박스 높이가 아니라
   화면 크기로 키워 공이 실제로 위로 솟구치게 한다. 수직 단위는 화면 높이. 수평 단위는
   "가장 멀리 가는 타구가 화면 폭 90% 지점에 멈추도록" 역산한다 — 그래서 공이 화면
   밖으로 나가지 않는다. 타구는 실제 시간의 0.65배 속도로 흘려 눈으로 따라갈 수 있게 한다.

`src/game/`의 순수 모듈은 이 변경에 관여하지 않는다 — 단위 환산은 전부 `draw.js`에서 한다.

## 창

`BrowserWindow`를 주 디스플레이의 `workArea` 크기로 띄운다(메뉴바·Dock 영역 제외).

- `transparent`, `frame: false`, `hasShadow: false`, `resizable: false`, `movable: false`,
  `focusable: false`, `skipTaskbar: true`
- `setIgnoreMouseEvents(true)` — 마우스는 전부 밑으로 통과
- `setAlwaysOnTop(true, 'screen-saver')`,
  `setVisibleOnAllWorkspaces(true, { visibleOnFullScreenWindows: true })`
- `app.dock.hide()` — 앱 전환기·Dock에 나타나지 않는다

## 판정 지연

전역 단축키는 main 프로세스가 받아 IPC로 렌더러에 넘긴다. 렌더러가 받는 순간의
`performance.now()`로 판정하므로 IPC 왕복만큼(수 ms) 늦게 잡힌다. 일정한 지연은 몸이
적응하는 종류라 우선 보정 없이 간다. 실제로 쳐보고 퍼펙트가 유의하게 안 나오면
`judge.js` 바깥에서 오프셋 상수 하나로 보정한다 — 판정 모듈 자체는 건드리지 않는다.

## 검증

- `npm test` — `src/game/`만. idle 규칙 테스트 추가.
- 오버레이 동작(클릭 통과, 항상 위, 전역 단축키, 트레이)은 `npm start` 후 수동 확인.
- 브라우저에서 `src/renderer/index.html`을 직접 열면 `Space`로 계속 동작해야 한다.
