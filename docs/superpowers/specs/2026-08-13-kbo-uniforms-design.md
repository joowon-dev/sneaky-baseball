# KBO 구단 유니폼 — 설계

2026-08-13

## 목표

타자와 투수에게 각각 KBO 10개 구단의 홈·원정 유니폼을 입힌다. 색만 칠하는 게 아니라
**실물 유니폼을 보고 찍은 픽셀 무늬**를 입힌다. 트레이 메뉴에서 고르고, 고른 값은 저장된다.

## 확정된 결정

- **선수는 계속 검은 실루엣이다.** 팔·다리·배트는 그대로 두고, **상의와 모자 자리에만**
  픽셀 무늬를 얹는다. 흰 글로우는 검은 실루엣이 계속 만들어 주므로 어떤 앱 위에서도
  읽히는 성질이 그대로 남는다. 포즈 4개도 그대로 쓴다.
- **유니폼은 색 몇 개가 아니라 작은 비트맵이다.** 1080 화면에서 타자는 48px, 몸통은
  가로 8 × 세로 14픽셀 — 도트를 찍기 딱 좋은 크기다. 색만으로는 홈 유니폼 10벌이
  흰색으로 뭉개지지만, **핀스트라이프·옆구리 패널·소매 트림** 같은 무늬는 이 크기에
  들어가고 그게 구단을 갈라 준다.
- **로고 이미지와 등번호는 쓰지 않지만, 가슴·모자 글씨는 글자로 찍는다.**
  처음엔 글씨 자리를 **색 띠 한 줄**로만 표현했다. 8px에 글자가 안 들어간다고 봤기 때문인데,
  실제로 입혀 보니 띠는 어느 구단이든 똑같이 생겨서 무지 흰색 유니폼 여섯 벌이 결국
  구분되지 않았다. 지금은 `TIGERS`·`Dinos`·`Bears` 같은 **짧은 워드마크**와 모자의
  **한두 글자**를 텍스트로 찍는다. 낱말은 짐작이 아니라 사진에 쓰인 그대로다.
  상표 이미지를 쓰는 게 아니라 성격이 맞는 서체로 조판할 뿐이다.
  게임 크기에서는 색이 있는 얼룩으로 뭉개지지만, 그 얼룩의 위치와 색이 곧 구단이다.
- **기본값은 `유니폼 없음`** — 지금의 검은 실루엣. 첫 실행에서 임의의 팀을 입히지 않는다.
- **타자와 투수는 완전히 독립적으로** 고른다. 같은 팀이어도 되고, 둘 다 없어도 된다.
- 판정·물리·타구는 한 줄도 바뀌지 않는다. 순수하게 그리는 쪽 변경이다.

## 자료 수집 — 무엇을 보고 찍었나

색과 무늬는 기억이나 위키 요약이 아니라 **구단 공식 판매처의 상품 사진**에서 왔다.
처음엔 나무위키 요약으로 팔레트를 짰는데 대조해 보니 절반쯤 틀렸다 — 삼성·kt·키움 홈이
전부 흰색인데 컬러로, NC가 네이비+금색인데 초록으로 적혀 있었다. 그래서 사진을 직접 봤다.

- 유니폼 18벌 + 모자 11개: [KBO마켓](https://kbomarket.com) 구단별 유니폼·모자 카테고리의
  「레플리카 홈/원정 유니폼」 상품 사진
- NC 홈·원정 2벌: [NC 다이노스 팀스토어](https://store.ncdinos.com)의
  「2026 리복 시그니처 홈/원정 유니폼」
- 색 값은 사진 픽셀에서 직접 뽑았다(바깥 8% 스튜디오 배경 제외 후 히스토그램).

사진은 참고용으로 본 것이고 저장소에 넣지 않는다. 결과물은 사진이 아니라 손으로 찍은
픽셀 무늬다.

**한화만 판단이 들어갔다.** 공식몰에 화이트·오렌지·다크·그레이 4벌이 있는데 화이트가
홈인 건 분명하고 원정은 **다크(`#282828`, 상품명은 '다크네이비'지만 실측은 거의 검정)** 로
정했다.

## 렌더링

### 포즈를 파트로 쪼갠다

지금 `src/render/sprites.js`의 포즈는 함수 하나가 전신을 `INK` 한 색으로 그린다.
이걸 객체로 바꾼다:

```js
export const batterStance = {
  silhouette(ctx) { /* 지금 batterStance 본문 그대로 */ },
  torso(ctx)      { /* 몸통 bone 하나 — 클립 경로로 쓴다 */ },
  torsoBox:  { x: -0.085, y: -0.80, w: 0.17, h: 0.38 },
  capBox:    { x: -0.12,  y: -0.98, w: 0.24, h: 0.15 },
}
```

포즈 4개(`batterStance`, `batterSwing`, `pitcherWindup`, `pitcherRelease`) 모두 같은 모양.
`torsoBox`/`capBox`는 픽셀 무늬를 어디에 얹을지 정하는 단위 공간 사각형이다.

### 레이어 순서

`drawFigure(ctx, pose, x, y, height, flip, glow, kit)`:

1. `glow`가 켜져 있으면 지금처럼 `silhouette`을 흰 그림자로 두 번 깐다.
2. `silhouette`을 `INK`로 그린다. — 여기까지가 현재 동작이고, `kit`이 없으면 여기서 끝난다.
3. `kit`이 있으면 `jerseyPath`로 **클립**을 잡고, 그 안에 무늬 비트맵을 그린다.
   클립을 쓰는 이유는 몸통이 둥근 끝(`lineCap: round`)을 가진 선이기 때문이다. 네모난
   비트맵을 그냥 얹으면 옆구리가 몸 밖으로 삐져나온다.
   다만 **위쪽 둥근 끝은 옷으로 덮지 않는다** — 어깨선 위로 반원이 혹처럼 솟아 옷이 아니라
   두건처럼 보인다. `jerseyPath`는 위를 어깨선에서 평평하게 자르고 아래만 둥글게 남긴다.
   잘라 낸 반원은 실루엣의 검정으로 남아 목덜미가 된다.
   같은 이유로 옆구리 패널도 **위에서 밑단까지** 솔기를 탄다. 처음엔 밑동에서 절반까지만
   솟게 그렸는데, 그러면 붉은 속옷을 입은 것처럼 보였다.
4. 모자(또는 헬멧)를 그리고, 그 위에 모자 글씨를 찍는다.

글로우가 1번에서만 걸리므로 무늬도 실루엣의 번짐 안에 들어앉는다.

### 픽셀이 픽셀로 보이게

무늬는 **가로 6 × 세로 9칸**짜리 격자다. 실제 몸통이 8×14px이니 한 칸이 1.3×1.5px쯤 되어
그대로 그리면 뭉갠다. 그래서:

- 키트마다 6×9 오프스크린 캔버스를 **한 번만** 만들어 캐시한다(20벌 × 54픽셀, 무시할 크기).
- 그릴 때 `ctx.imageSmoothingEnabled = false`로 두고 `drawImage`로 확대한다.

보간이 꺼져 있으므로 화면 크기가 어떻든 칸이 또렷한 네모로 남는다 — 이게 "픽셀화"의 핵심이다.

### 모자

모자는 무늬가 필요 없다. `{ crown, bill }` 두 색이면 충분하다.

- **크라운**: 머리 위쪽 절반을 덮는 호. 머리(`blob`, 반지름 0.1 안팎)보다 아주 살짝 크게
  그려 실루엣 경계에 검은 선이 한 줄 남게 한다.
- **챙**: 로컬 -x 방향으로 뻗은 납작한 호. 타자는 `flip=-1`로 오른쪽(투수)을, 투수는
  `flip=1`로 왼쪽(타자)을 보므로 **양쪽 다 로컬 -x가 바라보는 방향**이다. 포즈마다 챙
  방향을 따로 정할 필요가 없다.

### 좌우 반전

타자는 `flip=-1`이라 무늬도 뒤집힌다. KIA·NC처럼 옆구리 패널이 한쪽에만 있는 벌은 타자와
투수가 반대로 보인다. 실제 경기에서도 보는 각도에 따라 그러므로 그냥 둔다.

## 데이터 — `src/render/teams.js`

        panel: { color: '#C80828', style: 'sash' },     // 옆구리 — 격자 밖 곡선

/** 'kia-home' 같은 키를 키트로. 없는 키나 null이면 null(=실루엣). */

### 상의 말고 나머지

상의만 칠하면 검은 막대에 조끼를 걸친 꼴이 된다. 그래서 키트는 색 두 개를 더 갖는다:

- `base` — **옷감 색**. 윗팔(소매)을 이 색으로 덮는다. 격자에서 제일 많은 색을 세는
  방법도 있었지만 LG 홈처럼 핀스트라이프에 어깨 줄까지 있으면 검정이 흰색을 이겨
  소매가 뒤집힌다. 세는 게 아니라 사진을 보고 정하는 값이라 데이터로 받는다.
### 격자에 넣는 것과 안 넣는 것

격자는 **평평한 색면**만 담는다. 바탕과 어깨 절개선까지다. 나머지는 격자 밖에서
벡터·텍스트로 그린다:

| 요소 | 왜 격자 밖인가 | 데이터 |
|---|---|---|
| 핀스트라이프 | 6칸으로 쪼개면 검정이 절반을 먹는다 | `stripe` |
| 옆구리 패널 (KIA 사선 · NC 세로) | 격자로는 계단이 져 사선도 곡선도 안 나온다 | `panel: { color, style }` |
| 목 트림 | 어깨 곡선을 따라 도는 호다 | `trim[]` + `collar` |
| 소매 끝동 | 몸통이 아니라 소매에 있다 | `trim[]` |
| 가슴 워드마크 | 6칸에 글자가 안 들어간다 | `mark: { text, color, outline, style }` |
| 모자 글씨 | 격자는 상의 것이다 | `cap.mark` + `cap.markColor` |

**낱말은 사진에 쓰인 그대로 옮긴다.** 처음엔 팀 이름에서 짐작해 적었는데 절반이 틀렸다 —
KIA 가슴은 `KIA`가 아니라 `TIGERS`, NC는 `NC`가 아니라 `Dinos`, 키움은 `Heroes`가 아니라
`KIWOOM`이다. 모자도 마찬가지로 대개 이니셜 한 글자다 — KIA·LG가 나란히 `T`, 삼성이 `SL`,
롯데가 `G`, 한화가 `E`. 짐작으로는 절대 안 나오는 값이라 사진을 한 장씩 봐야 한다.

**글씨체는 성격만 맞춘다.** 구단 서체를 그대로 심을 수는 없으니 사진의 세 부류로 나눈다:

| `style` | 어떤 벌인가 | 어떻게 |
|---|---|---|
| `block` | TIGERS · TWINS · EAGLES(원정) | 곧게 선 굵은 대문자 |
| `slant` | KT WIZ · Giants · Dinos · KIWOOM | 기울임 변환을 건 굵은 대문자 |
| `script` | Lions · Bears · Landers · Eagles(홈) | 필기체. x-높이가 낮아 크기를 1.25배 준다 |

기울기는 폰트의 `italic`이 아니라 **기울임 변환**으로 준다. 굵은 서체는 italic 자체가 없는
경우가 많아 브라우저가 제멋대로 흉내 내거나 아예 곧게 나온다.

`outline`은 장식이 아니다. 검정 유니폼의 검은 TIGERS, 아이보리 위 빨강 Giants처럼
**바탕과 가까운 색으로 쓴 워드마크가 절반**이라, 테두리가 없으면 글씨가 옷에 묻힌다.
다만 글자가 6px보다 작아지면 테두리가 글자를 다 먹으므로 그때는 안 두른다.

**글씨는 변환을 풀고 장치 픽셀에 맞춰 찍는다.** 단위 공간에 그대로 `fillText` 하면 글자
크기가 소수점이 되어 흐려지고, 타자는 `flip=-1`로 그려지므로 글씨가 좌우로 뒤집힌다.
핀스트라이프에서 쓴 방법과 같다. 몸통 폭을 넘치면 가로로만 눌러 담는다 — 실제 유니폼
워드마크도 가슴 폭에 맞춰 좁혀져 있다.

**트림을 격자 줄로 넣으면 안 되는 이유**가 특히 중요하다. 처음엔 목·소매 트림을 0번 줄
전체에 칠했는데, 실제로는 소매 끝이나 목둘레의 얇은 곡선인 것이 가슴을 가로지르는 띠가
되어 버렸다. NC의 금색과 키움의 핑크가 특히 어색했다 — 입은 모양이 아니라 띠를 두른
모양이 된다.

**핀스트라이프는 격자에 넣지 않는다.** 6칸으로 쪼개면 검정이 절반을 먹어 굵은 줄무늬가
된다. 격자를 12칸으로 늘리는 것도 답이 아니다 — 몸통이 8px뿐이라 한 칸이 0.67px가 되어
줄이 들쭉날쭉 사라진다. 옷감 무늬는 색 블록보다 고운 단위라 `stripe` 색을 따로 받아
몸통 클립 안에 가는 선으로 긋는다.

이때 **장치 픽셀에 스냅해야 한다.** 단위 공간에서 그으면 선 위치가 픽셀 격자에 안 맞아
어떤 줄은 1px, 어떤 줄은 2px로 나오고, 그 비대칭이 굵기보다 더 눈에 거슬린다. 클립은
이미 잡혔으니 변환만 풀고 정수 좌표에 1px 폭으로 칠한다. 그러면 몸통 8px에 1px 줄 셋이
3px 간격으로 균일하게 선다.

바지는 키트 밖 상수(`PANTS`)다 — KBO는 홈·원정 가리지 않고 **흰 긴바지**를 입어
구단별로 갈리지 않는다. 다리의 86%를 덮고 끝에 남긴 검정이 스파이크가 된다.

허리에는 어두운 벨트 선을 긋는다. 없으면 상의와 바지가 한 덩어리로 붙어 원피스로 보인다.
타자는 모자 대신 헬멧을 쓴다 — 크라운이 크고 귀덮개가 붙는다. 어두운 헬멧은 실루엣에
묻히므로 챙을 머리 밖으로 길게 빼 쓴 티를 낸다.

바지는 공개 자료로 확인할 방법이 없었다 — 판매처는 상의·모자만 팔고, 상품 상세 시트도
상의 접사뿐이며, 나무위키 「현용 유니폼」 표도 같은 상의 컷이다. 위키미디어 커먼즈는 세
구단이 없고 나머지도 2012~2017년 사진이고, 구단 공식 선수단 페이지는 로그인을 요구한다.
처음엔 「홈 흰색 / 원정 옷감색, 무릎까지」로 넣었는데 둘 다 틀렸다. 실제로는 **구단과
무관하게 흰 긴바지**다.

### 남는 한계

20벌이 서로 다르긴 하지만, 8×14px에서 **띠 한 줄 차이로만** 갈리는 쌍이 있다:

- **LG 원정 · kt 원정** — 둘 다 검정 바탕에 어깨 흰 줄, 모자도 검정. 가슴 띠가 LG는
  빨강 전체, kt는 흰색에 빨강 한 점인 것만 다르다.
- **두산 원정 · 롯데 원정** — 둘 다 네이비 무지. 가슴 띠가 흰색/빨강으로 갈린다.
- **두산 홈 · 한화 홈** — 둘 다 흰 무지. 가슴 띠가 네이비/주황으로 갈리고 모자는
  거의 같은 어두운 남색이다.

실물도 서로 비슷한 벌이라 어느 정도는 불가피하다. 그려 보고 못 견디겠으면 다음 카드는
**격자를 8×12로 키우는 것** 이다 — 데이터 모양은 그대로고 칸만 늘어난다.

## 셸 — 트레이 메뉴와 저장

### 메뉴

`⚾` 메뉴에 서브메뉴 두 개를 붙인다:

```
최고 비거리  130m
⌥ 을 누르고 있는 동안 투구
스윙  ⌥Space
─────────────
타자 팀  ▸    유니폼 없음
투수 팀  ▸    ─────────────
─────────────  KIA 타이거즈 … 키움 히어로즈  (10칸)
숨기기 / 보이기  ─────────────
종료           홈 / 원정  (라디오 2칸)
```

서브메뉴는 13칸(없음 + 10구단 + 홈·원정). 현재 고른 항목에 체크 표시. `유니폼 없음`을
고르면 홈/원정 라디오는 회색으로 죽인다.

맥은 `NSMenu`/`NSMenuItem`에 `state = .on`, 윈도우 .NET 셸은 `ToolStripMenuItem`으로
같은 모양을 만든다.

### 저장

맥은 `UserDefaults`에 기존 `recordKey`와 같은 패턴으로 `batterKitKey`·`pitcherKitKey`
두 개(문자열, 없으면 실루엣). 윈도우 셸도 지금 최고 기록을 두는 자리에 같이 둔다.

### 브리지

`window.sneaky`에 두 가지를 더한다:

- **초기값 주입** — 페이지가 뜰 때 저장된 두 키를 넘긴다. 현재 최고 기록을 넘기는
  경로와 같은 자리.
- `setKit(who, key)` — 셸 → 웹뷰. 메뉴에서 고르는 즉시 `evaluateJavaScript`로 밀어
  넣어 다음 프레임부터 반영된다. `who`는 `'batter' | 'pitcher'`.

셸이 저장의 주인이다. 웹뷰가 셸에게 저장을 요청하는 경로(`saveKit`)는 만들지 않는다 —
고르는 곳이 메뉴뿐이라 필요가 없다.

## 브라우저 모드

`window.sneaky`가 없으면 메뉴가 없다. 조작 창구는 트레이뿐이라는 확정 결정을 유지하고,
개발 중 확인용으로 쿼리 파라미터만 읽는다:

```
index.html?batter=lg-home&pitcher=doosan-away
```

없으면 실루엣. 저장하지 않는다.

## 테스트

`test/`에 `teams.test.js`를 더한다. `src/render/teams.js`는 Canvas를 모르는 순수
모듈이라 지금 테스트 규약(순수 모듈만 테스트)에 그대로 들어맞는다.

- 10개 구단, 각 2벌
- 모든 `torso` 격자가 정확히 9줄 × 6칸이다
- 격자에 쓰인 모든 글자가 그 키트의 `colors`에 있다 — 오타 나면 투명해진다
- 모든 색이 유효한 `#RRGGBB`, 모자의 두 색도 마찬가지
- `kitOf`가 없는 키·`null`·빈 문자열에 대해 `null`을 준다
- 20벌의 (격자 + 색 + 모자) 조합이 모두 서로 다르다

실루엣 위에 무늬가 제대로 얹히는지, 픽셀이 뭉개지지 않는지, 어두운 앱·밝은 앱 위에서
읽히는지는 지금처럼 수동 확인이다.
