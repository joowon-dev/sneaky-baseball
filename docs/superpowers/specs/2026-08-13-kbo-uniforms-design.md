# KBO 구단 유니폼 — 설계

2026-08-13

## 목표

타자와 투수에게 각각 KBO 10개 구단의 홈·원정 유니폼을 입힌다. 트레이 메뉴에서 고르고,
고른 값은 저장된다.

## 확정된 결정

- **선수는 계속 검은 실루엣이다.** 유니폼은 그 위에 덧칠하는 색이지, 새로 그리는 그림이
  아니다. 흰 글로우는 검은 실루엣이 계속 만들어 주므로 어떤 앱 위에서도 읽히는 성질이
  그대로 남는다.
- **로고·워드마크는 쓰지 않는다.** 상표이기도 하고, 1080 화면에서 타자는 48px, 몸통은
  가로 8px이라 물리적으로 안 들어간다. 구단은 **색 배합으로만** 식별한다.
- **색 슬롯은 4개**: `jersey`(상의) · `trim`(파이핑) · `crown`(모자 위) · `bill`(챙).
  처음엔 상의+모자 2색으로 잡았으나, 홈 유니폼은 거의 전부 흰 상의라 모자색으로만
  갈리는데 검정 모자가 4팀(KIA·LG·KT·한화), 남색 모자가 3팀(두산·롯데·NC)이라
  홈 10벌이 실질 4가지로 뭉갰다. 야구모자는 원래 크라운과 챙이 따로 노는 물건이고
  챙은 3px쯤 되는 뚜렷한 모양이라, 여기서 슬롯 하나를 더 얻는다.
- **기본값은 `유니폼 없음`** — 지금의 검은 실루엣. 첫 실행에서 임의의 팀을 입히지 않는다.
- **타자와 투수는 완전히 독립적으로** 고른다. 같은 팀이어도 되고, 둘 다 없어도 된다.
- 판정·물리·타구는 한 줄도 바뀌지 않는다. 순수하게 그리는 쪽 변경이다.

## 렌더링

### 포즈를 파트로 쪼갠다

지금 `src/render/sprites.js`의 포즈는 함수 하나가 전신을 현재 `fillStyle`/`strokeStyle`
(항상 `INK`)로 그린다. 이걸 객체로 바꾼다:

```js
export const batterStance = {
  silhouette(ctx) { /* 지금 batterStance 본문 그대로 */ },
  jersey(ctx)     { /* 몸통 bone 하나 */ },
  cap(ctx)        { /* 크라운 호 + 챙 */ },
}
```

포즈 4개(`batterStance`, `batterSwing`, `pitcherWindup`, `pitcherRelease`) 모두 같은 모양.

### 레이어 순서

`drawFigure(ctx, pose, x, y, height, flip, glow, kit)`:

1. `glow`가 켜져 있으면 지금처럼 `silhouette`을 흰 그림자로 두 번 깐다.
2. `silhouette`을 `INK`로 그린다. — 여기까지가 현재 동작이고, `kit`이 없으면 여기서 끝난다.
3. `kit`이 있으면 `jersey`를 상의색으로 덧그린다. 2번에서 그린 몸통과 **같은 좌표의 같은
   선**이므로 정확히 덮인다.
4. `cap`을 크라운색·챙색으로 그린다.

글로우가 1번에서만 걸리므로 색칠한 부분도 실루엣의 번짐 안에 들어앉는다.

### 흰 상의 파이핑

흰 글로우 위에 흰 몸통을 칠하면 몸통이 통째로 사라진다. 상의 밝기가 임계값
(상대 휘도 0.7)을 넘으면 `jersey`를 두 번 긋는다 — 먼저 `trim` 색으로 굵게(`lineWidth`
0.17), 그 위에 상의색으로 얇게(0.11). 컬러 테두리가 남아 윤곽이 살고, 이건 마침 실제
홈 유니폼의 파이핑과 같은 모양이다.

임계값을 넘지 않는 상의는 한 번만 긋는다.

### 모자 모양

머리는 반지름 0.1 안팎의 `blob`이고 중심은 y ≈ -0.85. 모자는:

- **크라운**: 머리 위쪽 절반을 덮는 호. 머리보다 아주 살짝 크게(반지름 0.105) 그려
  실루엣 경계에 검은 선이 한 줄 남게 한다.
- **챙**: 로컬 -x 방향으로 뻗은 납작한 호. 타자는 `flip=-1`로 오른쪽(투수)을,
  투수는 `flip=1`로 왼쪽(타자)을 보므로 **양쪽 다 로컬 -x가 바라보는 방향**이다.
  포즈마다 챙 방향을 따로 정할 필요가 없다.

### 알려진 한계 — 가까운 조합

2색이 아니라 4슬롯이어도 완전히 갈리지는 않는다. 챙 하나로만 구분되는 쌍이 있다:

- **kt 홈 · SSG 홈** — 흰 상의 + 빨강 파이핑 + 빨강 크라운, 챙만 검정/빨강
- **KIA 원정 · SSG 원정** — 빨강 상의 + 검정 크라운, 챙만 검정/빨강
- **두산 홈 · 롯데 홈 · NC 홈** — 흰 상의 + 남색, 챙만 남색/빨강/금색
- **LG 원정 · kt 원정** — 검정 상의 + 빨강 파이핑, 크라운·챙 배치만 다름

실물도 서로 비슷한 조합이라 어느 정도는 불가피하다. 만들어 놓고 봤을 때 못 견디겠으면
**소매 끝 배색**을 슬롯으로 하나 더 여는 게 다음 카드다. 이번 범위에는 넣지 않는다.

## 셸 — 트레이 메뉴와 저장

### 메뉴

`⚾` 메뉴에 서브메뉴 두 개를 붙인다:

```
최고 비거리  130m
⌥ 을 누르고 있는 동안 투구
스윙  ⌥Space
─────────────
타자 팀  ▸    유니폼 없음
투수 팀  ▸    ─────────────
─────────────  KIA 타이거즈 … 키움 히어로즈  (10칸)
숨기기 / 보이기  ─────────────
종료           홈 / 원정  (라디오 2칸)
```

서브메뉴는 13칸(없음 + 10구단 + 홈·원정). 현재 고른 항목에 체크 표시. `유니폼 없음`을
고르면 홈/원정 라디오는 회색으로 죽인다.

맥은 `NSMenu`/`NSMenuItem`에 `state = .on`, 윈도우 .NET 셸은 `ToolStripMenuItem`으로
같은 모양을 만든다.

### 저장

맥은 `UserDefaults`에 기존 `recordKey`와 같은 패턴으로 `batterKitKey`·`pitcherKitKey`
두 개(문자열, 없으면 실루엣). 윈도우 셸도 지금 최고 기록을 두는 자리에 같이 둔다.

### 브리지

`window.sneaky`에 두 가지를 더한다:

- **초기값 주입** — 페이지가 뜰 때 저장된 두 키를 넘긴다. 현재 최고 기록을 넘기는
  경로와 같은 자리.
- `setKit(who, key)` — 셸 → 웹뷰. 메뉴에서 고르는 즉시 `evaluateJavaScript`로 밀어
  넣어 다음 프레임부터 반영된다. `who`는 `'batter' | 'pitcher'`.

셸이 저장의 주인이다. 웹뷰가 셸에게 저장을 요청하는 경로(`saveKit`)는 만들지 않는다 —
고르는 곳이 메뉴뿐이라 필요가 없다.

## 브라우저 모드

`window.sneaky`가 없으면 메뉴가 없다. 조작 창구는 트레이뿐이라는 확정 결정을 유지하고,
개발 중 확인용으로 쿼리 파라미터만 읽는다:

```
index.html?batter=lg-away&pitcher=doosan-home
```

없으면 실루엣. 저장하지 않는다.

## 테스트

`test/`에 `teams.test.js`를 더한다. `src/render/teams.js`는 Canvas를 모르는 순수
모듈이라 지금 테스트 규약(순수 모듈만 테스트)에 그대로 들어맞는다.

- 10개 구단, 각 2벌, 모든 슬롯이 유효한 `#RRGGBB`
- `kitOf`가 없는 키·`null`·빈 문자열에 대해 `null`을 준다
- 상의와 파이핑의 대비가 최소치를 넘는다 — 파이핑이 안 보이면 흰 상의가 사라진다
- 20벌의 4색 조합이 모두 서로 다르다 (겹치면 구분 자체가 불가능하다)

실루엣 위에 색이 제대로 얹히는지, 어두운 앱·밝은 앱 위에서 읽히는지는 지금처럼 수동
확인이다.

## 문서

`CLAUDE.md`의 **아트** 항목을 고친다 — 「배경 없는 검은 실루엣」에 유니폼 색이
얹힌다는 것과, 기본값이 실루엣이라는 것. **단축키**/**조작** 항목에 트레이 서브메뉴를
더한다.

## 범위 밖

- 로고·워드마크·등번호·선수 이름
- 소매 배색 슬롯 (위 「알려진 한계」 참고)
- 어웨이/홈에 따른 경기장·담장 색 변화
- 시즌별 얼트·서드 유니폼
- 유니폼에 따른 게임플레이 차이 — 순전히 보이는 것만 바뀐다
