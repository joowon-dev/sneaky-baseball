# Sneaky Baseball — 설계

작성일: 2026-08-12

## 컨셉

스페이스바 하나로 하는 측면 2D 야구. 투수가 던진 공을 타이밍 맞춰 쳐서 홈런을 노린다.
맞은 공은 타이밍에 따라 매번 다른 포물선을 그리며 담장 밖으로 날아간다.

## 확정된 결정

| 항목 | 결정 |
|---|---|
| 창 | 창틀 없는 커스텀 앱 창 (가로로 긴 900×320, 둥근 모서리, 자체 상단 바). 항상-위 아님 |
| 첫 위치 | 주 화면 왼쪽 아래 구석 |
| 스택 | Electron + HTML/Canvas 2D. 브라우저에서 `index.html`만 열어도 동작 |
| 시점 | 측면 2D — 왼쪽에 타자·포수, 오른쪽에 투수, 그 뒤에 담장 |
| 조작 | 스페이스바 한 키 (타이밍만) |
| 구종 | 직구 / 변화구 2종 |
| 판정 | 퍼펙트·굿·파울·헛스윙 (볼·스트라이크 카운트 없음) |
| 아트 | 밝은 바탕(`#f6f6f2`) 위 검은 실루엣 |
| 기록 | 최고 연속 기록 로컬 저장, 창 위치·크기 기억, 무음 |
| 단축키 | `Cmd/Ctrl+Shift+B` 즉시 숨김/복귀 |

## 게임 코어

투구 1개가 한 사이클이다. 볼·스트라이크 카운트는 없고 계속 던진다.

### 구종

- **직구**: 빠르고 직선. 기본 비행 시간 900ms.
- **변화구**: 느리고(1150ms) 막판에 아래로 떨어진다.

떨어지는 양은 `t³`(t = 진행률)에 비례해 후반에 몰린다. 여기에 매 투구마다
높낮이(`lane`, ±0.06)가 조금씩 섞여 같은 구종도 오는 높이가 다르다.

궤적 왜곡은 **화면상 위치에만** 적용되고 도달 시각(`flightMs`)은 바꾸지 않는다.
눈속임이 곧 난이도다.

### 판정

스페이스를 누른 시각과 공이 타격점을 지나는 시각의 오차로 결정한다.

| 오차 (절대값) | 타이밍 | 결과 |
|---|---|---|
| ≤ 35ms | 퍼펙트 | **홈런** |
| ≤ 80ms | 굿 (빠름/늦음) | **안타** |
| ≤ 150ms | 파울 | 파울 — 기록 변화 없이 재투구 |
| 그 외 | 헛스윙 | 헛스윙 |
| 안 침 | 견제 | 헛스윙 |

### 타구 궤적

결과별 고정 궤적이 아니라, **타이밍 오차와 공의 높낮이에서 발사 속도와 각도를
계산한다.** 그래서 같은 홈런도 매번 다르게 날아간다.

- 힘 `power = 1 − |오차| / 150` → 속도 `MAX_SPEED × (0.35 + 0.65 power)`
- 발사각 `32° − 오차 × 0.11 − 높낮이 × 40`, 8°~62°로 묶음
  - 빠르게 휘두르면 퍼올려 높이 뜨고, 늦으면 낮게 깔린다
  - 낮은 공은 각도가 깎여 땅볼에 가까워진다
- 파울은 같은 크기로 뒤쪽(포수 방향)으로, 힘은 절반
- 좌표 단위는 x·y 모두 "필드 높이" — 창 크기가 바뀌어도 궤적 모양이 유지된다

퍼펙트 타구는 담장(타격점에서 필드 높이의 약 2.3배)을 넘어간다.

### 스코어

- 누적 홈런 수, 누적 안타 수
- 현재 연속 (안타 이상이면 +1, 헛스윙이면 0, 파울은 유지)
- 최고 연속 기록 (로컬 저장)

### 난이도

누적 홈런 수에 따라 서서히 오른다.

- 구속: `flightMs × max(0.62, 1 − 홈런×0.02)`
- 변화구 비율: `min(0.55, 0.25 + 홈런×0.03)`

## 화면

가로로 긴 측면 뷰. 필드 좌표는 0~1 비율이라 창을 늘려도 배치가 유지된다.

```
   ╭──────────────────────────────────────────────────────────╮
   │ ● SNEAKY BASEBALL        홈런 12   연속 3   최고 7     ✕ │ ← 자체 상단 바
   ├──────────────────────────────────────────────────────────┤
   │                        ○ ← 날아가는 공                    ┊ ← 담장
   │      🯅 타자                    ● ← 오는 공        🯅 투수  ┊
   │   🯅 포수   │ 타격점                                      ┊
   ╰──────────────────────────────────────────────────────────╯
```

- 창틀이 없으므로 둥근 패널·테두리·상단 바를 캔버스가 직접 그린다
- 상단 바 높이만큼 투명한 HTML 요소를 겹쳐 드래그 손잡이로 쓴다
  (`barHeight()` 하나를 캔버스와 HTML이 공유해 높이가 어긋나지 않는다)
- 닫기는 상단 바 오른쪽 `✕` (HTML 버튼 → IPC → `app.quit()`)
- 타격점에 세로 눈금을 두고, 공이 굿 윈도우 안에 들어오면 진해진다 — 타이밍 기준점
- 공은 잔상 몇 개를 남겨 속도와 궤적이 보이게 한다
- 글자 크기·여백·공 크기는 창 높이(기준 320px)에 비례한다
- 밖으로 나가는 공은 필드 영역에서 잘린다

## 구조

```
src/main/     main.js    창 생성·전역 단축키·IPC
              preload.js contextBridge (window.sneaky)
              store.js   userData JSON 영속화
src/game/     pitches.js 구종 정의·궤적·난이도   ← 순수
              judge.js   오차 → 판정             ← 순수
              batted.js  타구 발사·포물선         ← 순수
              engine.js  게임 상태 전이           ← 순수
src/render/   sprites.js 실루엣 포즈 드로잉
              draw.js    프레임 렌더
src/renderer/ index.html, style.css, app.js  루프·입력
test/         judge / engine / pitches / batted 단위 테스트 (vitest)
```

`src/game/`은 Electron과 Canvas를 전혀 모르는 순수 모듈이다. 판정·궤적·상태 전이를
테스트로 못박고 그 위에 렌더링을 얹는다. 모든 시간 입력은 인자로 받아(`now`)
테스트에서 결정적으로 검증할 수 있다.

### 데이터 흐름

```
keydown(space) ─┐
                ├→ engine.swing(state, now) → judge → 새 state
rAF tick ───────┘   engine.tick(state, now) (미스윙 만료 처리)
                         │
                         ├→ draw.js (state, now) → Canvas
                         │     └→ batted.battedFlight(결과, 오차, 높낮이)
                         └→ 최고 기록 변경 시 IPC → store.js
```

## 에러 처리

- `state.json`이 없거나 깨졌으면 기본값으로 조용히 시작한다.
- 저장된 창 위치가 현재 디스플레이 밖이면 왼쪽 아래 기본 위치로 되돌린다.
- 전역 단축키 등록 실패 시(다른 앱이 점유) 콘솔 경고만 남기고 계속 실행한다.
- `window.sneaky`가 없으면(브라우저로 직접 열었을 때) 기록을 localStorage에 저장한다.
- 포커스를 잃어도 애니메이션이 멈추지 않도록 `backgroundThrottling`을 끈다.

## 테스트

`src/game/`의 순수 모듈을 vitest로 검증한다.

- `judge`: 각 윈도우 경계값(35/36, 80/81, 150/151), 빠름·늦음 구분, 미스윙
- `engine`: 결과별 스코어 변화, 최고 연속 갱신, 파울의 기록 불변, 잘못된 페이즈에서의
  입력 무시, 만료 처리, 진행률
- `pitches`: 난이도에 따른 구속·변화구 비율 경계, 높낮이, 후반에 몰리는 낙차
- `batted`: 타이밍이 어긋날수록 짧아지는 비거리, 1ms 차이도 궤적을 바꾼다는 것,
  빠른 스윙의 높은 발사각, 각도 클램프, 파울의 역방향, 포물선의 상승·하강

렌더링과 Electron 창 동작은 수동 확인한다.
